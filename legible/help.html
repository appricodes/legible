Legible - Help

Legible scans documents, runs OCR (text recognition) on them, and exports the result to HTML or PDF - built with screen readers in mind from the ground up.

Getting started

Add page (scan)

Add page scans directly from your scanner and runs OCR on it - no chooser dialog appears; which scanner, resolution, color mode, and paper source to use are all configured once in Settings. If your scanner's paper source is set to Automatic Document Feeder, one click of Add page scans every page currently loaded in the feeder and adds them all, one after another.

Both the scan and the OCR step run in the background behind a progress dialog (see Background jobs below) - the window stays responsive, and you can cancel partway through.

Export and More menus

Two more buttons sit next to Add page, each a popup menu:

  • Export (Ctrl+2) - Export to PDF and Export to HTML.
  • More (Ctrl+3) - Import files..., Start new session, Settings..., About Legible..., and Help.

Once a menu is open, each item has its own underlined-letter shortcut, same as any menu. Add page itself also has a Ctrl+1 shortcut, matching Export's Ctrl+2 and More's Ctrl+3 - all three work anywhere in the window, and are each button's only shortcut (deliberately no Alt+ mnemonic, so a screen reader announces the real Ctrl+1/2/3 shortcut instead of a mismatched one).

Import files

Import files... (in the More menu) loads existing image files (PNG, JPEG, TIFF, BMP) or multi-page PDFs instead of scanning from hardware - each page runs through OCR exactly like a fresh scan.

Managing pages

The Scanned pages list on the left shows every page in the current session, in order. Selecting a page renders its recognized content - real headings, paragraphs, and tables, not a flattened text dump - in the Page preview (HTML) box on the right: the exact same HTML Export to HTML would write for that page, shown in a real HTML-rendering widget a screen reader can navigate by heading and table, the same way it would navigate a web page.

Upside-down pages

Every scan/import gets a best-effort check for whether it was fed in rotated 180° (needs Tesseract installed - see the README; if it's missing, this is simply skipped). If a page is detected upside down:

  • It's recognized and exported right-side up automatically - the text is read correctly, and the PDF export shows it corrected.
  • Its default title gets a note right after the page number, before the text preview - so it's the first thing you see or hear: "Page 3 (scanned upside down - rotate 180° before filing): ..." - so you know which way to turn the paper original when filing it.
  • You hear a spoken "Upside down page" cue right away (via Windows text-to-speech, audible even without a screen reader running), plus the usual status announcement.

Only 180° is corrected (the common "fed the page in upside-down" mistake) - the original scan file itself is never modified.

Page titles

Every page gets a title automatically the moment it's added: "Page 1: [first ~128 characters of its text]". This number is assigned once, when the page is added, and stays fixed from then on - moving pages up or down (or deleting/adding others around them) never renumbers an existing page's title. Only Rename changes a title, replacing it completely with whatever you type (no more auto "Page N:" prefix gets added back to a renamed page).

Reorder, delete, rename

Move up, Move down, Rename, and Delete (removes the selected page, after a confirmation) all live in a context menu on the page itself, not as buttons: right-click a page (or press the keyboard Menu key / Shift+F10 with a page selected - no mouse needed) to open it. Each item shows its existing keyboard shortcut too (Ctrl+↑/Ctrl+↓ for Move up/down, F2 for Rename, Delete for Delete), so those still work directly without opening the menu at all.

Re-OCR all pages

Re-OCR all pages... (the only per-page-list action left as a button, since it acts on the whole session, not just one page) lets you pick a different OCR backend and re-run it on every page, discarding each page's current recognized text and replacing it with the new backend's result. Handy for comparing backends, or redoing a session after realizing the wrong backend or language was configured. It doesn't touch page order, images, or custom titles - only the recognized text - and asks for confirmation first, since it can't be undone.

Background jobs & the progress dialog

Scanning, importing, re-OCR, and exporting all run behind a blocking progress dialog with a Cancel button. The main window is unusable until the job finishes or is cancelled - this stops you from, say, deleting a page while it's mid-export - but the dialog itself never freezes: the actual work happens in the background and the dialog's text/progress bar update live (e.g. "Page 2 of 5: Reading the page text (block 3 of 8)..." while scanning, "Saving page 3 of 11..." while exporting).

Cancel stops the job at the next safe point - between pages/items, and (for OCR) between recognized blocks within a page. It can't interrupt a scanner driver or an OCR engine's single recognize step already in progress, only stop before starting the next one. Whatever completed before you cancelled is kept (pages already added or re-OCR'd stay in the session); a cancelled export never leaves a partial file on disk.

Short synthesized sound effects also mark the key moments - scan start, OCR start, OCR finished, import finished, export finished, and any error - an audible cue alongside the progress dialog's text, useful even when you're not looking at the screen. They need no setup and work regardless of whether a screen reader is running.

Exporting

  • Export to HTML - a clean, text-only version with structure kept as real HTML tags (headings, tables, paragraphs). No images.
  • Export to PDF - each page shows the scanned image, with an invisible text layer underneath that screen readers can read (so the PDF both looks like the original scan and is fully accessible). Every heading/paragraph is its own individually tagged PDF structure element - not one undivided block of text per page - so Adobe Reader's Read Aloud and screen readers pause between them instead of reading the whole page as one run-on sentence. Page images are re-encoded as JPEG at Settings' PDF image quality, and capped to Settings' PDF image DPI relative to their printed size - both together can shrink an otherwise huge, losslessly-embedded scan down several times over with no visible difference at normal viewing/print sizes.

Neither export shows a confirmation dialog when it finishes - the status line (spoken immediately) and a short sound cue are enough. Only an export error still shows a dialog.

Settings

SettingWhat it does
Scanner backend / deviceWhich scanning interface (WIA/TWAIN/SANE) and which physical scanner to use.
Paper sourceFlatbed, Automatic Document Feeder, or Automatic (leave the scanner's own current source untouched) - only offered when the selected scanner actually supports it.
Resolution (DPI)Scan resolution.
Color modeColor, grayscale, or black & white.
OCR backendOCR always runs through Docling (real headings/tables); pick EasyOCR (broadest language support, slower, needs PyTorch) or RapidOCR (fast, lightweight, no PyTorch) as its text-recognition backend.
Preferred languageApplied to whichever engine is active - matters a lot for accuracy (diacritics, punctuation, or an outright missing language pack).
PDF image qualityJPEG quality (5-100) for each page's image in the PDF export.
PDF image DPIMaximum resolution (50-300) for each page's image in the PDF, relative to its printed size - lower-resolution scans/imports are never upsampled past their own resolution.
If Docling or the selected backend isn't actually installed, or the selected language isn't supported by it, Settings pops up a warning explaining exactly what's missing/unsupported and how to fix it - rather than silently falling back to a placeholder result later.

Accessibility notes

  • The interface is built with wxPython, which wraps the operating system's native controls, so screen readers (NVDA, JAWS, Narrator, VoiceOver, Orca) read everything natively.
  • The page list announces each item and its position (e.g. "3 of 8") as you arrow through it.
  • A status line at the bottom announces what just happened (page added, moved, exported, etc.) and is spoken immediately when something worth hearing occurs.
  • Every background job's progress dialog also speaks its own progress at each meaningful step, and returns keyboard focus to its Cancel button in between.

Troubleshooting

  • OCR gives placeholder/mock text - Docling or the configured backend's package isn't actually installed, or the selected language isn't supported by it; Settings will show which backend is really active, and will warn you directly about what's wrong.
  • Add page fails immediately - no scanner backend is installed or configured, or nothing responded; use Import files... to load an existing image or PDF instead, or check the scanner backend section of the README.
  • Unsaved changes warning - shown when you try to start a new session or close the app after adding, deleting, reordering, or re-OCR'ing pages since your last export (renaming a page alone doesn't trigger it, since titles aren't saved into the PDF/HTML output).
