# Core
Pillow>=10.0
reportlab>=4.0
# Synthesizes the app's UI sound effects (legible/sounds.py) - kept as an
# explicit core dependency (not just whatever docling/scikit-image pull in
# transitively) so sound effects work even with no OCR backend installed.
numpy>=1.24

# PDF rendering, used by Import to rasterize multi-page PDFs into per-page
# images (no poppler/Ghostscript dependency).
pypdfium2>=4.0

# GUI toolkit. wxPython wraps native OS controls, which screen readers (NVDA,
# JAWS, Narrator, VoiceOver, Orca) read natively. Tkinter is NOT used because
# it exposes no accessibility tree on Windows.
wxPython>=4.2

# --- OCR: always via Docling (layout/heading/table detection); pick at
# least one text-recognition backend to use in Settings ---
# Both need a *language* to recognize non-English/Chinese text correctly;
# set it once in Settings (see legible/languages.py).

# Docling itself: layout detection (paragraphs, headings, tables). Its own
# layout/table-structure model weights download automatically on first use
# and are cached after that - no OCR backend on its own, see the two
# extras below.
docling>=2.40

# EasyOCR backend (docling[easyocr]): broadest language coverage (80+
# languages), but slowest and heaviest - depends on PyTorch (a large,
# GB-scale download; CPU-only is fine, no GPU required). Its recognition
# model downloads automatically on first use and is cached after that.
docling[easyocr]>=2.40

# RapidOCR backend (docling[rapidocr]): lightweight ONNX text recognition,
# faster and lower-footprint than EasyOCR, no PyTorch dependency, and
# covers every language Legible offers (including the one - Greek - EasyOCR
# doesn't). Needs an inference backend package; onnxruntime is the simplest
# (CPU, no extra setup).
docling[rapidocr]>=2.40
onnxruntime>=1.18

# --- Upside-down page detection (optional - see legible/orientation.py) ---
# Purely a nice-to-have layered on top of OCR: if missing, pages just never
# get auto-rotated/flagged, nothing else changes. Uses Tesseract's OSD
# (orientation-and-script-detection) mode only - never reads page text, so
# this is unrelated to (and much cheaper than) the old "Tesseract OCR
# engine" option that was removed. Needs the same separate, non-pip
# `tesseract` binary as that used to (see README):
#   Windows: https://github.com/UB-Mannheim/tesseract/wiki
#   macOS:   brew install tesseract
#   Linux:   apt install tesseract-ocr
pytesseract>=0.3.10

# --- Scanner backends (install the one for your OS to enable real scanning) ---
# Choose the device, resolution, and color mode once in Settings; Add page
# then scans directly with no chooser dialog. Without one of these installed
# (or with none configured), Add page reports a clear error - use Import to
# load an existing image/PDF instead.
